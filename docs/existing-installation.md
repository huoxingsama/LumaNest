# 接管已有影院数据

桌面影院、设置和后台使用同一个已安装的 LumaNest 发行包。已有安装可以继续使用原数据目录、端口和缓存，不需要维护另一套 Python 源码或逐文件同步 UI。

实例设置目录保存 `config.json`、DPAPI 凭据、运行状态和备份。`foundation.runtime_directory` 指向运行数据目录，空值使用实例设置目录下的 `runtime`。既有 `data/mpv-shim` 内的个人播放选项、脚本、主题与图片缓存，以及目录索引和缓存文件，均原地保留。修改一个已经应用的运行数据目录不会自动搬迁数据。

## 预览与导入

先为发行包准备一个新的实例设置目录。使用安装了发行包的 Python 运行：

```powershell
python -m personal_cinema.existing_installation --home C:\CinemaSettings --runtime-directory C:\CinemaData --options C:\PrivateConfig\migration-options.json
```

默认只预览。`--options` 是平铺的设置对象，可省略；它用于明确第三方服务地址、已有 libMPV/ffprobe 路径，以及来源的驱动、稳定根 ID 和写权限。不要把该文件放进公开仓库。预览不会显示令牌、密码或 PIN。

确认内容后，在同一命令加 `--apply`。导入只保存新实例的配置和加密凭据，不启动服务、不移动影片、不改写原运行配置。已有配置或非空凭据库不能被此入口覆盖。新用户来源默认只读；仅明确提供的来源权限会保留。人工指定资料和其他旧运行配置不会被整体清空。

导入保留当前播放用户、设备 ID、PIN 和其他账户。后台管理员授权与原播放账户令牌分别保存。旧账户文件在导入时保留，首次启动影院后由账户模块加密归档，再清除已迁移的明文副本。DPAPI 数据仅由原 Windows 用户解密。切换前应保留旧安装及配置的私人备份。

## 切换运行程序

1. 退出播放，备份原配置和启动入口。
2. 停止旧版本的后台、定时任务与监督进程，防止自动拉起旧进程。Jellyfin、OpenList 可以继续作为已有第三方服务运行。
3. 使用发行包的设置入口检测基础服务与内置播放引擎，应用设置，然后启动后台和影院。
4. 将桌面入口和自启入口指向发行包的 `lumanest` 命令。不要再运行旧项目的 `run.py` 或旧后台脚本。

如果旧服务仍占用媒体接口端口，应用/启动会明确拒绝，不会把旧服务误当成本实例启动成功。媒体库目录、用户权限、真实播放、远程设备连接及网络出口仍需在目标机器验证。程序不会自行迁移 HypoMux、系统防火墙或端口转发规则；依赖可执行文件路径的网络规则必须同步保留或重新配置。

内置播放引擎优先从当前 Python 环境的 `player/mpv-2.dll` 读取运行库，也支持显式选择已有 DLL。外置 MPV 是可选方式，不是首次启动的前提。监听地址默认仅本机；确实需要远程客户端时可显式开放媒体接口，设置服务始终只在本机开放。

这套流程是数据接管，不是跨平台迁移工具，也不负责搬运媒体文件。若需回退，应先停止发行版全部进程，再恢复私人备份与原入口，避免两套后台同时修改同一数据目录。
