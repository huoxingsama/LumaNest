## 本轮额外修复

- 默认硬件解码正确传递 `auto-safe`，不再退回软件解码。
- 顺序缓冲使用配置的缓存位置和容量；完成区块可立即复用。
- 顺序缓冲和离线分块共用源指纹，同路径同大小换源不会混入旧字节。
- 同实例重复打开设置复用已有进程；运行操作跨进程串行化。
- 本地媒体库没有缓存 worker 时，也检查播放和暂停状态。
- 配置应用使用同一 revision 快照；更新期间的新保存保持待应用状态。
- 备份恢复可重入读取配置，且保留当前设置进程的握手，恢复后仍能重新打开页面。
- 认证请求与媒体 CDN 重定向分开，跨域不转发服务凭据。
- Jellyfin 使用兼容的合并认证头，修复有效账户被误报为未授权的问题。
- 日常入口与自启使用统一启动器，保留自定义解释器的网络身份；停止维护另一套私人界面代码。
- 既有 MPV include、字幕顺序与缓冲参数保留；默认内置播放器和完整海报规则。

## 仍需真实环境验收

本轮连接了既有 Jellyfin/OpenList，核对来源权限并打开真实影院；没有移动用户影片、执行云端整理或实播用户影片。
启动与界面验证不代表每个云盘驱动、真实网络吞吐或显卡 HDR 输出均已验证。
校园网自动切换、HypoMux 自动路由、跨平台发行等未实现能力见 [实施记录](implementation-ledger.md)，不能把本预览标为稳定版或无人值守通用安装器。
